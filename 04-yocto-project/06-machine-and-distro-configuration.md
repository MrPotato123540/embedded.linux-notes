# Machine and Distro Configuration

> **Applies to:** PetaLinux 2024.1 · Zynq UltraScale+ MPSoC

**[04 · The Yocto Project](README.md)** · Part III: Build Systems

## Concepts

`MACHINE` selects hardware-related metadata. `DISTRO` selects system policy. Keep these responsibilities separate: a board description should not silently decide every product package or login policy.

`local.conf` holds build settings. `site.conf` can share site policy. `auto.conf` is often generated by automation. PetaLinux also generates configuration from its project settings, so inspect the include chain before editing a file under `build/conf`.

## Reference project

The inspected BSP's `local.conf` contains a weak default for `zynqmp-generic`, but `plnxtool.conf` assigns `MACHINE = "xilinx-zcu106"`. Reading only the first file would give the wrong answer. The final BitBake value and its assignment history are what matter.

The machine selects CPU tuning, kernel and bootloader choices, device-tree inputs and supported output behavior. A generated machine configuration can combine exported hardware information with the AMD layers. Keep the hardware export and machine metadata from the same design revision.

## CPU tuning and multiconfig

Compiler tuning controls instruction selection and package architecture. An SDK name containing `cortexa72-cortexa53` does not prove that the board contains Cortex-A72 cores. Read the tune configuration and actual device specification before drawing that conclusion.

A **multiconfig** build uses several configurations within one build system. This is useful when Linux for the A53 and firmware for another processor need different toolchains or settings. `BBMULTICONFIG` enables named configurations; explicit dependencies connect their outputs. It does not make unrelated processors share one executable format.

## Pitfalls

- A generated configuration can overwrite a manual edit on the next configuration run.
- Two boards with the same CPU may still need different memory, peripheral and boot settings.
- A layer's machine name and an exported hardware platform name need not be identical.
